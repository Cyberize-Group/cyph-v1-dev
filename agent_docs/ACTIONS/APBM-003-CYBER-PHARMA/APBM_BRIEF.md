## 1. Objective and intended user

**Target One.** Frank's testers (and Coach) sign in to the existing staging URL with prepared email/password accounts and use OwedBook and the agreed admin read views against **real rows in the shared dev Supabase**, where those rows are **synthetic pharmacies** generated by a governed fixture generator. They can check who sees which store, click through every OwedBook screen, and find bugs. Calculation values are prepared fixtures; the math engine is a later module (APBM-005).

**Phase 3 closes inside this module.** The Phase 3 exit gate from plan v2.0 §5, Controlled Read Validation (owner-A sees only A's rows on the actual screen, every read in `audit_logs`), passes as part of Target One's acceptance.

**What Target One is not:** not a payment flow (APBM-007), not live claims or the calculation engine (APBM-005), not emails or PDFs (APBM-006), not production (APBM-008), not real patient data anywhere (D-2).

## 3. In scope (the eight internal stages of E2, in order)

Each stage ends with its own instrument green and a journal entry; none requires a Director message except stage 5.

1. **Ownership and permission delta** (D-4): account-owner reach across every store in the owner's account; `my_business_ids()` (or equivalent helper) extended to include stores of accounts the user owns; owner-only mutation fence on `accounts` and `subscriptions`; at-most-one-admin-per-store constraint; `user_roles.superadmin` keeps its Cyberize-internal meaning (display labels mapped, never repurposed). → `CONTRACTS/OWNERSHIP_AND_AUDIT_CONTRACT.md`
2. **Signup-trigger correction** (CE-2): `handle_new_user()` redefined so no metadata ever determines privilege; fixed `member` role; `full_name`; SECURITY DEFINER; pinned `search_path`.
3. **Read-audit closure** (D-1(a)): every OwedBook app read through the audited `owedbook_*` wrappers; ordinary authorized users' direct reads on `user_data` revoked so they cannot bypass the audit; admin read views through their own audited security-definer paths; audit event counts per a defined operation contract.
4. **Synthetic fixture generator + seed/reset** (CE-1, E-13, E-17): the Target One cast (one-store owner; three-store owner who also administers one store; separate store admins; members with assigned access; an unrelated account), identities created server-side with explicit `user_roles`/`profiles` writes; claims that obey all seven locked money rules; every status chip, both money signs, several PBMs, AAC hit and miss; `system_config` Alabama rows; deterministic, idempotent, safe reset boundaries; scripted zero-identity scan. `mocks/owedbook.ts` regenerated from the same source (R-05).
5. **Harness rework and disposable-target proof**: isolation matrix updated for D-1(a) and D-4 (expected-change list from E1), CF-8/CF-9 harness repairs, `rls:prove` + `audit:prove` green from a from-scratch replay on SCRATCH. Then **DECLARED STOP — APPLY CHECKPOINT (Director)**: `APPLY_CHECKPOINT.md`. Cody resumes only on the Director's recorded resolution.
6. **Service swap and admin read paths on dev**: `services/owedbook.ts` internals → the four wrappers; `services/adminDemo.ts` read paths → real reads (stores, members, audit viewer, billing status read-only); writes stay mock with a visible "unavailable in this release" state (R-06); R-016 error/loading/refresh/empty states, smallest permitted component change.
7. **Board and regression**: build, typecheck, full suite green; component diff versus the baseline limited to the permitted R-016 paths.
8. **Staging deployment and factual handoff**: the authorized candidate deployed to the existing OwedBook staging target through the agent-owned deployment workflow under Director authorization; `QAM/QAM_MANIFEST.md` and `QAM/HANDOFFS/ENGINEERING_HANDOFF.md` completed; `APBM_STATE.md` → `E2 COMPLETE — AWAITING QA BRANCH`.
