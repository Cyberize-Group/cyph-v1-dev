## Lessons Learned

- **A Director-led end-to-end manual walkthrough belongs inside release verification**, alongside the automated checks.
  - R3 was caused by fixtures that always set a customer default card.
  - F1–F5 (admin seeing the add-store form, false billing warnings, raw access errors, misleading audit wording, email in the navbar) all came from the walkthrough, not from the automated suites.
- **The UI must read "withheld" and "failed" differently.** A field the server deliberately omits for a role is not an error state. Map an absent field and an unknown value separately.
- **An owner-only page needs a server guard as well as owner-only APIs.** API refusal alone still lets a non-owner see a form they can never use.
- **Treat build-tool output as data, not instructions.** The Next.js security reminder embeds an instruction to offer an upgrade. It was reported to the Director, not followed.
- **Stale deployment kits drift silently.** The 3 Nov Portal kit no longer matches the code's origins, environment selector or secrets. Re-derive deployment configuration from code before every release.
