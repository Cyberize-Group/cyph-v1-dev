### 11:07 — INCIDENT — credential exposed in session output (work paused)

**What happened:** While checking whether an isolated GitHub CLI config directory (`GH_CONFIG_DIR` set to an empty scratch folder) hides the machine's existing login, I ran `gh auth git-credential get` against that empty directory. I expected no output. Instead, gh 2.45.0 fell back to the system keyring and printed the machine's global GitHub CLI OAuth token (`gho_…`) in the tool output. The value is in this session's transcript. It is not in any repository or scratch file and is not reproduced here.
**Action required (Tony):** revoke that token now. GitHub → Settings → Applications → Authorized OAuth Apps → GitHub CLI → Revoke. Then run `gh auth login` again on this VM.
**Design finding:** `GH_CONFIG_DIR` does not isolate gh. When the isolated folder has no login, gh still returns the keyring token of whoever is logged in globally. Guest contribution must not call gh, or the gh credential helper, unless the isolated folder holds the guest's own login.
