# APBM synthetic seed

The generator constructs every claim from integer indexes and fixed numeric reference inputs. It reads no legacy fixture, export or patient file. Seed: `APBM003_SYNTHETIC_V1`; surrogate UUIDs are SHA-256-derived. Five stores A1/B1/B2/B3/C1 each receive 50 claims. Seven Auth identities use reserved `example.invalid` mailboxes and random per-run passwords; no Operator. Public account ownership/junctions match the approved cast (3 accounts, 8 memberships). User roles and profiles are explicitly written.

NDCs are artificial `00000000001`–`00000000004`, names start SYNTHETIC, Rx identifiers contain SYNTHETIC/store/index. Patient/contact fields stay NULL. Dates cycle June 1–28, 2026; reference vintage is January 1, 2026. Status cycles all five chips. Three synthetic PBMs plus unmatched rows have BIN/PCN/group-derived keys. AAC takes precedence; brand WAC multiplies by .96; generic WAC is bounded by FUL. Rate rounds to 5 places, expected to cents after adding 10.64. Paid is constructed from signed owed, including overpayments. Updated payment pairs occur every third row. Federal/report fields in the mock remain NULL to match v1 wrappers.

Audited insert plan: accounts 3 + businesses 5 + junctions 8 + subscriptions 3 + dataset versions 4 + AAC 2 + WAC 4 + FUL 1 + PBM 3 + claims 250 + config 2 = **285**. Public inserts run in one SQL transaction with service_role claims and NULL actor; the runner verifies count and attribution before commit. Auth creation precedes it and is not atomic with public seeding; a failure leaves a named partial-seed receipt for Director recovery. No automatic DEV retry/reset.

Use complete target prefix and APBM evidence flags documented in the APPLY evidence. `run.mjs` requires a fresh private `/tmp` credential path, writes mode 0600, refuses existing seeded accounts, and never logs passwords. `reset.mjs` only accepts confirmed SCRATCH and deletes deterministic seed IDs plus the seven named Auth identities; audit rows/non-seed users/Storage remain untouched. DEV seed is Tony-only, once after approved forward apply.

`verify.mjs` reads every seeded column and recomputes all 250 claim calculations independently in SQL. Canonical comparison excludes surrogate primary IDs and generated created/updated/joined timestamps; Auth UUID references normalize to reserved email handles. Other fields, foreign-key associations, status, quantities, money, configuration and reference vintage remain included. `--attack` is SCRATCH-only: changes one claim in a rolled-back transaction and requires the hash to change; the scanner must reject a synthetic patient-field leak. Two reset/run cycles must yield identical canonical hashes. `generate.mjs --write-mocks` regenerates A1 fixtures only, with no connection.
